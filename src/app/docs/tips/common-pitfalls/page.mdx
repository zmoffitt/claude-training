# Common Pitfalls

Mistakes to avoid when working with AI coding tools.

<div className="max-w-2xl lg:max-w-3xl">

| Pitfall | The tell | Fix |
|---|---|---|
| Trusting without verifying | It compiled, so it merged | [Read it like a PR](#trusting-without-verifying) |
| Losing context in long sessions | The model contradicts an earlier decision | [Rewind, compact, or restart](#losing-context-in-long-sessions) |
| Over-engineering | Abstractions nobody asked for | [State the scope](#over-engineering) |
| Hallucinated APIs | An import that does not resolve | [Check the package and version](#hallucinated-apis) |
| Copy-pasting sensitive data | A real token in a prompt | [Sanitize first](#copy-pasting-sensitive-data) |
| Ignoring test failures | A failing test "fixed" to pass | [Run the suite before and after](#ignoring-test-failures) |

</div>

## Trusting without verifying

<Lead tone="red">The problem:</Lead> Accepting AI-generated code without reading it.

<Lead tone="amber">Why it happens:</Lead> AI output looks confident and often compiles. It's tempting to merge without a thorough review.

<Lead tone="green">The fix:</Lead> Treat AI code like any other PR — read every line, run the tests, check edge cases.

## Losing context in long sessions

<Lead tone="red">The problem:</Lead> After many back-and-forth messages, the AI loses track of earlier decisions and starts contradicting itself.

<Lead tone="green">The fix:</Lead>
- Use `/rewind` in Claude Code to drop a failed attempt instead of arguing with it
- Use `/compact` to summarize and free up context (Claude Code also auto-compacts near the limit)
- Start a new session for unrelated tasks
- Restate important constraints when switching topics

## Over-engineering

<Lead tone="red">The problem:</Lead> AI tends to add abstractions, error handling, and configurability beyond what's needed.

<Lead tone="green">The fix:</Lead> Be explicit about scope:
```
Keep it simple. No need for error handling beyond what's already in the codebase.
Only implement the exact feature described — no extras.
```

## Hallucinated APIs

<Lead tone="red">The problem:</Lead> AI suggests library functions or APIs that don't exist.

<Lead tone="green">The fix:</Lead> Always check that suggested packages exist and that the API matches the current version. Verify imports compile before committing.

## Copy-pasting sensitive data

<Lead tone="red">The problem:</Lead> Sharing production logs, customer data, or credentials in AI prompts.

<Lead tone="green">The fix:</Lead> Sanitize data before sharing. Replace real values with placeholders. Never paste API keys or tokens.

## Ignoring test failures

<Lead tone="red">The problem:</Lead> AI fixes the code but breaks existing tests, then "fixes" the tests to match the broken behavior.

<Lead tone="green">The fix:</Lead> Run the full test suite before and after changes. If a test needs updating, verify the behavioral change is intentional.

<Callout variant="warning" title="A test that suddenly passes is a finding" align="left">
  When an edit turns a red test green without touching the code under test,
  the test was changed, not the behavior. Read the test diff before the code
  diff.
</Callout>
