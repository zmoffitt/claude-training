# GitHub Copilot

<ReadTime minutes={4} />

Autocomplete that reads your file. Useful every day, and not the job the program trains you for.

## Where it fits

Copilot lives in the editor and predicts the next lines from the file you have open and the tabs beside it. That makes it the right tool for the typing half of the work: finishing a function whose shape is obvious, filling in a test from its name, writing the fourth Terraform resource that looks like the first three. It is the "Human IN the loop" era from Session 1, and it stays useful after you move on, because most of a day is still typing.

Copilot has an agent side too: an agent mode in VS Code that edits across files and runs tasks, a coding agent that takes a GitHub issue to a pull request, and repo-level instructions in `.github/copilot-instructions.md`, its answer to <Term id="claude-md">`CLAUDE.md`</Term>. The program still routes that work to Claude Code. Not because Copilot cannot do it, but because <Term id="plan-mode">plan mode</Term>, <Term id="hook">hooks</Term>, <Term id="subagent">subagents</Term>, <Term id="scheduled-task">scheduled tasks</Term>, and the permission model live in one place, and the sessions teach that place. When the task is "make the login flow support SSO" rather than "complete this line", switch.

| You want to… | Reach for |
| --- | --- |
| Finish the line, the loop, the obvious test | Copilot inline completion |
| Explain or refactor the block under the cursor | Copilot Chat, or Claude Code if it spans files |
| Ask where something is handled in the repo | Copilot Chat with `@workspace`, or Claude Code |
| Change behavior across several files, with tests | Claude Code |
| Investigate a bug you can't localize | Claude Code with subagents |
| Automate something on a schedule | Claude Code scheduled task |

## Setup

[Editor Setup](/docs/configuration/editor-setup) has the extension list and sign-in steps for both editors. Current VS Code ships Copilot built in, so there is nothing to install: sign in from the Copilot icon in the status bar with your GitHub account. In JetBrains, install the plugin and sign in via **Tools > GitHub Copilot > Login to GitHub**.

Two surfaces to know on day one:

- **Inline completion** shows as ghost text as you type. `Tab` accepts, `Esc` dismisses.
- **Copilot Chat** answers questions and edits on request: inline on a selection with `Ctrl+I`, or in the chat panel. Type `#file:` to pull another file into the question. The shortcuts are on [Productivity Shortcuts](/docs/tips/productivity-shortcuts#github-copilot).

## Getting good completions

Inline completion sees the open file and your other open tabs, so give it something to read.

- **Write the comment first.** A one-line intent above the function is the prompt: `// return the CA policies that exclude the break-glass account`.
- **Name things properly.** `stalePolicies` gets a better completion than `arr`.
- **Give it the signature.** Type the function name and parameters, let it fill the body, then read the body.
- **Keep a reference open.** A sibling file with the pattern you want is the strongest context Copilot has.
