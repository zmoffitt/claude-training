# Choose an Extension

Add only the capability your workflow needs.

<div className="max-w-2xl lg:max-w-3xl">

| Need | Mechanism | Example |
| --- | --- | --- |
| A rule for every repository task | `AGENTS.md` | Preserve public API compatibility |
| A repeatable procedure | Skill | Review an incident runbook |
| Access to another system | Approved plugin or MCP connection | Read a ticket and its status |
| A distributable bundle | Plugin | Team skills and required connections |
| Work on a recurring cadence | Scheduled task | Draft a weekly change digest |
| Deterministic validation | Script or CI check | Validate YAML syntax |

</div>

These layers can work together. A skill describes the process, a connection supplies evidence, and a schedule determines when to run it. Keep the operational rules in one maintained place. [Customization overview](https://learn.chatgpt.com/docs/customization/overview).

## Start with the smallest useful workflow

For an incident runbook review, begin with an attached file and a written checklist. After the workflow succeeds, package the checklist as a skill. Connect a document system only if manual file selection is the actual bottleneck. Schedule the review only when recurring output has an owner.

**Decision exercise:** a teammate asks for “an agent that handles tickets.” Identify the intended output, source system, write permissions, review point, and trigger. Choose mechanisms after those details are explicit.
