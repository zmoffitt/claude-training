<ReadTime minutes={7} />

## Which model for which job

Pick the starting model and <Term id="effort">effort</Term> from the kind of work, then adjust from what you see. The effort column is the Claude Code setting; `medium` is the default there for all four models.

| Work | Start on | Starting effort |
| --- | --- | --- |
| Everyday engineering, debugging, multi-PR features | Opus 5.5 | `medium`, then `high` |
| Computer use and vision-heavy workflows | Opus 5.5 | `medium` |
| Well-scoped coding: bug fixes, feature iteration, spec-driven work | Sonnet 5.5 | `medium`, then `high` for harder tasks |
| Chat and interactive sessions | Sonnet 5.5 | `low` or `medium` |
| Everyday documents, slides, spreadsheets | Sonnet 5.5 | `medium` |
| Repeated agent tasks: investigation, review, drafting | Sonnet 5.5 | `medium` |
| <Term id="subagent">Subagents</Term> that search files, read logs, summarize | Haiku 5.5 or Sonnet 5.5 | Model default |
| Classification, routing, tagging, bulk extraction | Haiku 5.5 | `medium` |
| Major refactors, migrations, architecture planning, leading many subagents | Fable 5.2 | `medium`, then `high` |
| Deep research; scientific or quantitative analysis | Fable 5.2 | `medium`, then `high` |
| Not sure | Opus 5.5 | `medium` |

**A clear spec does not mean Sonnet by default.** A migration or a performance pass can be fully specified and still need Opus 5.5, or Fable 5.2 for the large ones. Complex financial models and work over large source material also start on Opus. The table follows Anthropic's [model selection guide](https://claude.dev/blog/which-claude-model-should-you-build-with/) from November 2026.

## When the model is not getting there

Change one thing at a time, in this order:

1. **Give it a way to check its work.** A test, a build, or a script that calls the endpoint. A model that can verify finds its own mistakes a turn earlier, and one test run costs less than more thinking on every turn.
2. **Raise effort one level.** Higher effort buys more verification, more tool calls, and more edge-case testing. It does not add knowledge or skill the model lacks.
3. **Move up a model, at a lower effort than you were using.** Do not carry `xhigh` from Opus to Fable; start Fable at `medium` or `high`.

**Past `high`, switch models instead of pushing effort.** One more effort level can cost as much as the next model up. In Anthropic's runs, Fable 5.2 at `high` scored about level with Opus 5.5 at `max` on FrontierCode 2.0 (45.3% against 45.5%) for roughly half the cost per task, and Opus 5.5 at `xhigh` gained about 1.4 points on SWE-bench Pro over `high` for 2.5 times the cost.

## Moving up to Fable 5.2

**What it is for.** Fable 5.2 is Anthropic's most capable generally available model, built for the hardest technical projects: work Opus 5.5 at `high` could not finish, long runs nobody is watching, and large changes that coordinate many subagents. Between the two, Opus 5.5 is the better fit for work you steer turn by turn, at half the price. Mythos 5.2 offers the same capabilities, but only to organizations verified through Anthropic's programs such as the Cyber Verification Program.

**What it costs.** $8 / $40 per million tokens, down from $10 / $50 on Fable 5.1, with output up to 30% faster. That is twice Opus 5.5 on uncached input and output, but cache reads cost the same $0.20, so the gap is narrowest on long, cache-heavy sessions and widest on tasks that write a lot. On subscription plans Fable can bill to usage credits; the `/model` picker says so before you select it.

**How to brief it.** Describe the outcome and the finish line, hand over the whole problem including the ambiguous parts, and drop the "remember to verify" reminders. Two habits worth a line in your prompt: at `low` and `medium` effort it sometimes ends a turn with a list of what remains, so say when to keep going; and when nobody says who owns the code, it tends to build onto the existing structure and report nearby problems instead of fixing them. It also delegates readily, and subagents can be a large share of what a session costs, so pin their models.

**Switching has a price.** The prompt cache belongs to the model that wrote it, so the first turn after `/model` pays the cache-write price on the whole conversation, and Fable's reasoning from earlier turns does not carry to any other model. Run `/compact` first or start a fresh session from a short written plan, switch at a natural break, and switch back when the hard part is solved. `/model` also saves your choice as the default for new sessions unless you apply it with `s` for this session only.

**Flagged requests fall back to an older model.** Fable 5.2, Opus 5.5, and Sonnet 5.5 run safety classifiers that mostly flag cybersecurity and biology content, which makes them relevant to security work. In Claude Code a flagged request on Fable or Opus 5.5 re-runs on Opus 4.8 (cybersecurity) or Opus 5 (biology), with a notice in the transcript; on Sonnet 5.5 a cybersecurity flag re-runs on Sonnet 5. The session stays on the fallback until you run `/model`, so check which model answered before you trust a security review. To be asked first, set "Switch models when a message is flagged" in `/config`.

**Organization limits.** On the API, Fable 5.2 requires 30-day data retention and is not available under zero data retention without Anthropic's sign-off.

## Current pricing

API list prices per 1M tokens, November 2026, from the [official pricing table](https://platform.claude.com/docs/en/about-claude/pricing). Subscription plans draw on plan limits instead of billing per token, but a cheaper model still stretches those limits further.

| Model | Input / output | Cache read | Fast mode (in / out) |
| --- | --- | --- | --- |
| Fable 5.2 | $8 / $40 | $0.20 | $16 / $80 |
| Opus 5.5 | $4 / $20 | $0.20 | $8 / $40 |
| Sonnet 5.5 | $2 / $10 | $0.10 | Not available |
| Haiku 5.5 | $0.10 / $0.50 up to 100K-token prompts, $0.50 / $2.50 above | $0.01, then $0.05 | Not available |

All four have a 1M-token context window and 128K maximum output. Fast mode (`/fast`) runs the same model at up to 2.5× the output speed for twice the token price; on subscription plans it bills to usage credits only, never to plan limits.

## Legacy models you'll still meet

The previous generation is still served, and some providers resolve the `opus`, `sonnet`, and `haiku` aliases to it. If `/model` shows one of these, you're usually on a third-party platform, on an older org default, or in a session that fell back after a flagged request.

| Model | Price (in / out per 1M) | Where it still shows up |
| --- | --- | --- |
| Fable 5.1 | $10 / $50 | What `fable` resolved to before Claude Code v2.1.321; now selected by ID, `claude-fable-5-1` |
| Fable 5 | $10 / $50 | What `fable` resolves to in Claude apps gateway sessions |
| Opus 5 | $5 / $25 | Older Enterprise org defaults; the fallback for flagged biology requests |
| Opus 4.8 / 4.7 | $5 / $25 | The fallback for flagged cybersecurity requests (4.8); fast mode on 4.8 is removed on 30 Nov 2026 |
| Opus 4.6 | $5 / $25, 200K unless `[1m]` | The `opus` alias on Microsoft Foundry |
| Sonnet 5 | $2 / $10 | The auto-mode classifier model; the fallback for flagged cybersecurity requests on Sonnet 5.5 |
| Sonnet 4.6 | $3 / $15, 200K unless `[1m]` | The `sonnet` alias on Claude Platform on AWS |
| Sonnet 4.5 / Haiku 4.5 | 200K only | `sonnet` on Bedrock, Google Cloud, and Foundry (Sonnet 4.5 is also Foundry's default model); `haiku` on Claude Platform on AWS, Bedrock, Google Cloud, and Foundry |

**Aliases move.** `best` used to pick Fable where it was available; from v2.1.321 it resolves to the same model as `opus`. Organizations on third-party platforms should pin versions with `ANTHROPIC_DEFAULT_OPUS_MODEL` and its siblings so an alias never changes under them. The [model configuration reference](https://code.claude.com/docs/en/model-config) lists what every alias resolves to per provider.
