# Worked Example: CA Drift Watch

<ReadTime minutes={3} />

All five guardrail layers, end-to-end, on one real IAM problem: a daily watch for Conditional Access policy drift, Graph read-only, GitHub ticket on drift.

## The shape of it

- **Trigger:** daily cloud scheduled task, 06:00.
- **Tools:** Microsoft Graph (read), GitHub (issue create).
- **Steps:** snapshot CA policies → diff vs. yesterday → classify each change → file a ticket if material.
- **Subagents:** one per change, classifying impact in parallel.
- **Level:** 3 read, 0 writes to Entra.

## The five guardrail layers in this workflow

Each row maps to one of the [five guardrail layers](/docs/training/claude-code/session-4/designing-guardrails), under the same number.

| Layer | In this workflow |
| --- | --- |
| **1. `CLAUDE.md` constraints** | `"never call CA write endpoints; report only"`. The agent reads this every session. |
| **2. Permission scoping** | Deny `Bash(mg-graph * patch *policies*)` in `.claude/settings.json`. Enforcement, not just instruction. |
| **3. Plan-then-execute** | The orchestrator skill emits a numbered plan before any classification runs. |
| **4. Checkpoints & escalation** | Stop and ask if more than five policies changed in one day. Drift that big means something is happening that the task should not handle alone. |
| **5. Definition of done** | A markdown file in `runs/yyyy-mm-dd.md` with all diffs and links. If that file does not appear, the run did not complete. |

<Callout variant="info" title="Why this is a fair Level 3 candidate" align="left">
  Read-only Graph access, write surface is just a GitHub ticket, blast radius is "humans review the report." If the agent misclassifies a change, the worst outcome is a wrongly-labeled ticket — not a misconfigured tenant.
</Callout>
