# MCP Architecture

<ReadTime minutes={3} />

A protocol — not a product. Open standard, any client, any server.

Claude is the **client**. An **MCP server** exposes tools and data over JSON-RPC, running over stdio (local) or streamable HTTP (remote). The server brokers calls to an external system (Microsoft Graph, GitHub, Kubernetes, a database) and returns results. You stay in the loop, approving or denying each tool call.

## Three primitives

- **Tools:** functions Claude can call (`create_ticket`, `list_users`)
- **Resources:** data Claude can read (logs, dashboards, docs)
- **Prompts:** pre-built prompt templates the server offers

## Local vs. remote

- **Remote-first (streamable HTTP)** reaches web, mobile, and managed agents. The older SSE transport is deprecated; `claude mcp add --transport http` falls back to it only when a server offers nothing else
- **Local (stdio)** is the developer-loop case: quick to iterate, single user

The same protocol works in Claude Desktop, Claude Code CLI, and the web — write a server once, use it everywhere.

<Callout variant="success" title="Open standard, broad adoption" align="left">
  MCP is governed under the Linux Foundation's Agentic AI Foundation alongside
  Agent Skills, and the major agent platforms speak it. Servers you build work
  with any compliant client: current Claude, future Claude, third-party agents
  in your stack. Claude Code also defers MCP tool definitions behind **tool
  search** by default, so a server with 50 tools no longer costs 50 tools'
  worth of context on every turn.
</Callout>
