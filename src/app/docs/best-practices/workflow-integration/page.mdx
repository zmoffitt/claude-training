# Workflow Integration

What to hand to the model at each stage of a change, and what stays yours.

## Development lifecycle

<div className="max-w-2xl lg:max-w-3xl">

| Stage | Delegate to AI | You still own |
| --- | --- | --- |
| **Planning** | Brainstorm approaches, draft a design outline, map the code a change touches | The decision, and the constraints you give it |
| **Implementation** | Scaffolding, boilerplate (tests, configs, migrations), the first pass at complex logic | Reading every line before it merges |
| **Review** | A first-pass review, the PR description, explaining unfamiliar code to reviewers | Business logic, architecture, cross-team impact |
| **Debugging** | Reading stack traces and logs, proposing a root cause, suggesting fixes with edge cases | Confirming the fix in the real environment |

</div>

## Team workflow

### Sharing prompts

When you find a prompt that works well:

1. Document it in the [Tips & Tricks](/docs/tips/effective-prompts) section
2. Include the tool name, the prompt, and example output
3. Note any caveats or limitations

### Pair sessions

Schedule regular pair sessions where team members demonstrate their AI workflows. This is the fastest way to spread knowledge.
